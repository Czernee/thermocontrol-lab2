# ТермоКонтроль - лабораторная работа 2

Учебная программная часть информационной системы мониторинга температуры
помещения. Ядро не зависит от конкретного мессенджера: внешний адаптер передает
в приложение идентификатор канала и команду пользователя.

Реализовано:

- виртуальный датчик температуры с периодом 1 с и шагом 0,1 °C;
- проверка диапазона -40...85 °C;
- буфер до 300 допустимых отсчетов;
- скользящее среднее по пяти последним отсчетам;
- SQLite и шифрование измерений AES-GCM;
- вход по логину и паролю, PBKDF2-HMAC-SHA-256, временные сессии;
- отдельная проверка права пользователя на датчик через подписку;
- работающий шлюз сообщений с длинным опросом Bot API;
- вывод времени в понятном формате по часовому поясу пользователя;
- команды `/start`, `/status`, `/history`, `/limits`, `/logout`;
- автоматические тесты и запуск в Docker Compose.

## Хранение данных и секретов

Учетные записи, соли и хеши паролей, сессии, подписки и измерения хранятся в
`data/thermocontrol.sqlite3`. Исходные пароли в базе и конфигурационных файлах
не сохраняются. Ключ шифрования измерений находится в
`data/thermocontrol.key`.

Токен внешнего шлюза передается контейнеру как Docker secret из локального
файла `secrets/bot_token.txt`. Каталоги `data/` и `secrets/` исключены из Git.
Файл `.env` для запуска системы не используется.

UTC применяется только для внутреннего хранения и сравнения времени. В ответах
пользователь видит, например, `05.11.2026 17:10:24 МСК`. Bot API не передает
часовой пояс устройства, поэтому используется поле `User.timezone`; для новой
учетной записи его значение по умолчанию равно `Europe/Moscow`.

## Проверка без внешнего шлюза

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py --demo
python -m unittest -v
```

## Запуск в Docker

1. Создайте локальные каталоги `data` и `secrets`.
2. Поместите токен шлюза единственной строкой в `secrets/bot_token.txt`.
3. Один раз создайте учетную запись. Пароль вводится интерактивно и не
   отображается:

```powershell
docker compose run --rm thermocontrol python main.py --create-user student `
  --db /app/data/thermocontrol.sqlite3 `
  --key /app/data/thermocontrol.key
```

Если учетная запись уже существует, но пароль неизвестен, задайте новый пароль
без удаления истории измерений:

```powershell
docker compose run --rm thermocontrol python main.py --set-password student `
  --db /app/data/thermocontrol.sqlite3 `
  --key /app/data/thermocontrol.key
```

4. Соберите и запустите систему:

```powershell
docker compose up -d --build
docker compose logs -f thermocontrol
```

Остановка выполняется командой `docker compose down`. Данные сохраняются в
локальном каталоге `data/` и не удаляются при пересоздании контейнера.

## Локальный запуск шлюза

После создания пользователя и файла токена шлюз можно запустить без Docker:

```powershell
python main.py --bot `
  --db data/thermocontrol.sqlite3 `
  --key data/thermocontrol.key `
  --token-file secrets/bot_token.txt
```
